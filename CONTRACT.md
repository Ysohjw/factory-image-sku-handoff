# Factory image SKU handoff contract 0.1.1-beta.1

Free local beta, tested on Windows with Python 3.12. Workbook content is data, never instructions. Only process files you are authorized to use.

## Invocation and output

`python scripts/handoff.py INPUT.xlsx --sheet Products --sku-column A --image-columns B --first-data-row 2 --output NEW_DIRECTORY`

Sheet name and the row-oriented layout must be explicitly declared. Column arguments are uppercase Excel letters; image columns are a comma-separated list. Input extension must be `.xlsx`. The output directory must not exist; input and output cannot overlap. No network, Excel automation, macros, formula calculation, external relationship resolution, or source writes are used.

Success/review writes `manifest.json` and `assets/<sha256>.<png|jpg>`. Original image bytes are not decoded/re-encoded for export. Shared bytes have one asset and multiple occurrences. SKU values never become file paths. JSON is UTF-8, deterministic, sorted keys, no timestamps or absolute source paths. The source workbook SHA-256 and tool version are recorded. Exit 0 = every inventoried image occurrence and SKU row is eligible under the declared layout, with no unresolved issues; exit 2 = output requires human review; exit 1 = fatal rejection, one JSON error on stderr, no output directory. A missing-image row or unsupported layout therefore cannot return 0. Nothing claims confirmed semantic ownership, website upload readiness, image URLs, or product identity beyond the declared layout.

## Mapping and uncertainty

Manifest top-level fields: `schema_version`, `tool_version`, `source_sha256`, `layout`, `status`, `assets`, `occurrences`, `rows`, `issues`. Assets contain stable ID/SHA-256, original byte length, detected PNG/JPEG format, safe relative output path, and original package member(s). Occurrences contain stable sequential ID, source part, drawing anchor evidence, referenced asset ID when available, candidate row/cell, exact SKU evidence, disposition (`eligible` or `review`), and reason codes. Rows report candidate SKU cells and image counts, including rows that have a SKU but no image. Issues include code and scope; no executable markup is produced.

Text SKUs preserve Unicode, whitespace, punctuation, and leading zeroes exactly. SKU evidence contains `value`, `data_type`, and `number_format`; blank, numeric, Boolean, error, formula, and date values require review. Date evidence uses ISO text with its original data type, never a guessed identifier. Exact duplicate text SKUs, more than one image on a candidate row, hidden candidate row/image or SKU column/sheet, or any merged range intersecting candidate SKU/image cells require review. Blank SKU rows with images are inventoried. An image above the first data row, outside declared image columns, outside the selected sheet, absolute/unanchored, or spanning rows is review. SKU rows without an image are review.

Two-cell drawings are eligible geometrically only when their markers lie wholly inside one declared image cell: start offsets are nonnegative; end marker is in the same row/column, or precisely the next row/column boundary with zero relevant offset; end cannot precede start. One-cell drawings use a declared start-column and single-row rule: the start column must be declared, row and column offsets must be nonnegative, width and height positive, and the explicit finite positive row height must contain the row offset plus image height. The row height is converted from points to EMU (12,700 EMU per point); a missing explicit row height is `ROW_HEIGHT_UNKNOWN` and is not replaced by a guessed default. Horizontal extent is recorded but does not establish horizontal cell containment or semantic ownership. Absolute anchors always require review. All geometry is drawing evidence interpreted under the user-declared row layout; final semantic ownership remains a human responsibility.

Every image occurrence and every media package member must be accounted for. Unreferenced media is `UNREFERENCED_MEDIA`; unsupported media is retained as inventory evidence without export. PNG/JPEG media must pass signature and basic decoder format verification without re-encoding. Unknown WPS `DISPIMG`, Excel richData/in-cell images, VML, grouped drawings, or other unsupported drawing objects trigger explicit review; absence of supported images cannot yield exit 0. A mismatch between package inventory and proven parser objects is a fatal `PARSER_INVENTORY_MISMATCH`, not silent omission. No-image inputs yield a review manifest.

## Parser and hostile-package boundaries

Use installed openpyxl 3.1.5 for workbook cells/metadata and its drawing model parser for anchors. ZIP/XML inspection is only a security/inventory guard, not a replacement handwritten XLSX parser. The bounded XML guard uses installed lxml 6.1.1 with networking and entity resolution disabled, after encoding and DTD/entity checks. Pillow 12.3.0 verifies supported media. Dependencies are recorded, not vendored or downloaded.

Reject archives with absolute/traversal/backslash/drive-like member names, noncanonical path components, case-insensitive duplicate members, encrypted members, symlink/nonregular members, malformed ZIP, missing package/workbook roots, macro/VBA/ActiveX/OLE/embedded executable parts, any external relationship, XML DTD/entity declarations, invalid XML, or unsupported XML encoding (only UTF-8/ASCII with optional UTF-8 BOM). Reject formulas only as SKU eligibility; never evaluate formulas anywhere. Formula text containing image functions is inventoried as unsupported layout. Output is published only after all checks pass; unexpected failures also produce no partial output. Refuse overwrite, including preexisting empty directories and symlinks.

Fixed limits: input archive 20 MiB; 2,000 members; 100 MiB total declared or actual expanded bytes; 20 MiB per member; 200:1 per-member compression ratio for members over 1 MiB; XML/rels 5 MiB each; 100,000 XML elements per part and 500,000 XML elements in total; 100,000 actual worksheet cell elements in total and 100,000 cumulative merged-range cells (range areas, counted before parser materialization); 50 worksheets; 10,000 rows and 256 columns per worksheet (declared or actual); 1,000 media members; 2,000 image occurrences; 10 MiB per supported image; 25 million decoded pixels per image; 4,096 characters per SKU. Limits are inclusive; one unit beyond is rejected. Only existing cells and image candidate rows are considered; the implementation must not materialize the full rectangular grid across sparse sheets. Empty compressed sizes with nonempty entries reject. Malformed metadata, unreasonable row/column geometry, broken internal relationship targets, and nonfinite numbers reject or cause explicit geometry review before output; they never promote an image to eligible.

## Validation boundary

Synthetic tests establish only the tested local behavior. A person must confirm that an image actually depicts its candidate SKU. The output does not establish storefront acceptance, real factory accuracy, paid demand, or a production security certification. Nonzero two-cell horizontal offsets require review; nonzero vertical offsets require an explicit row height. Nonstandard workbook or worksheet XML filename extensions and opaque relationships other than image or printer-settings parts are unsupported.
